# Positioning one-pager — LaunchOS

Dunford-style canvas. The tool that runs launches must itself be positioned
sharply — this page is part of the work sample.

| | |
|---|---|
| **For** | PMMs and PMs who run launches out of scattered docs, decks and Slack threads |
| **Who** | lose hours answering "where are we?" and catch asset drift only after publishing |
| **LaunchOS is** | an open-source launch room: one URL where the brief, the tier, the timeline, the readiness gate and every asset live — and stay consistent |
| **Unlike** | GTM ops platforms (e.g. Ignition — priced and built for ops teams running many launches) and static launch templates (which go stale the day the brief changes) |
| **It** | generates the whole kit from one brief, checks every asset against the brief for drift, and gives stakeholders a read-only URL instead of a meeting |
| **Proof** | open demo launch (no sign-up); the consistency check runs live; code and prompts are public — audit the rubric |

## Message hierarchy
1. **Hero:** "Your launch, in one URL."
2. **Support:** one brief in → plan, gate and the full asset kit out — and a
   checker that flags any asset that drifts from the brief.
3. **Proof point:** open the demo launch room in 10 seconds; fork it and run
   your own launch on your own keys.

## Distribution story (BYO-key)
Hosted = showcase: a polished sample launch plus a small daily budget of live
generations. Real use = clone the repo, add your keys: your launches, your
tokens, zero trust required. "Fork me" is the CTA where platforms put
"Book a demo."

## Honest competitive note
Ignition and similar GTM platforms do more, for teams that run launch programs.
LaunchOS deliberately serves the solo PMM with one launch on fire this quarter —
free, single-player, nothing to procure. Positioning = segment choice, not a
feature race.
